# Operating Rules

用于 `wave-tracking-validation` 的交互与安全约束。项目门禁与分析、看板、营销、Catalog 技能一致，以 SKILL.md 的「项目门禁」一节为准。埋点设计与落地阶段的写入规则见 `wave-tracking` 的同名文件。

## 必守规则

- **先过项目门禁**：任何项目级 MCP 调用前，先按 SKILL.md 的「项目门禁」一节确认项目；禁止静默假定项目。
- **只读**：本技能不写入任何平台数据。修计划、改 Pipeline、改 SDK 代码、改 Catalog 元数据都交给对应技能，不要在这里代劳。
- **列选项，再执行**：先说明质检范围、推荐和影响，再调用工具。
- **不要替用户重启或部署环境**：不能代替用户重启本地项目、移动端 App、前端 Dev Server、后端服务或部署环境；只能明确提示由用户手动重启 / 重新部署项目。
- **不要假设埋点已经生效**：代码改动、SDK 初始化或计划发布之后，都要等待用户自行验证事件已实际触发。
- **不要默认发起质检**：即使用户已经确认事件触发，也只能在用户明确表示“开始质检”后再调用质检相关工具。
- **按阶段加载文件**：只读取当前阶段需要的 prompts 和 playbooks，不要一次性把全部资料灌进上下文。
