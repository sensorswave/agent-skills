# Operating Rules

用于 `wave-tracking` 与 `wave-tracking-validation` 的统一交互与安全约束。项目门禁与分析、看板、营销、Catalog 技能一致，以各自 SKILL.md 的「项目门禁」一节为准。

## 必守规则

- **先过项目门禁**：任何项目级 MCP 调用前，先按 SKILL.md 的「项目门禁」一节确认项目；禁止静默假定项目。
- **必填最少化，默认尽量补齐**：只向用户追问真正缺失且会影响结果的必填信息；名称、说明、目标平台、排序等可合理推断的参数，优先由 AI 自动生成默认值，再在写入前统一给用户确认。
- **列选项，再执行**：先说明选项、推荐和影响，再调用工具；涉及写操作时必须二次确认。
- **先展示将提交的参数**：创建、更新、发布前先列出要写入的字段，避免误操作。
- **Tracking Plan 是实施主线**：在 `wave-tracking` 中，Pipeline 选择或创建、项目级 SDK 接入、埋点代码修改和 Dashboard 交接都必须基于已发布的 Tracking Plan。本次流程中新建或更新的计划必须在本次流程中经用户明确确认并成功发布后才能继续；用户不发布就停在草稿态。
- **不要替用户重启或部署环境**：不能代替用户重启本地项目、移动端 App、前端 Dev Server、后端服务或部署环境；改完埋点代码后，只能明确提示由用户手动重启 / 重新部署项目。
- **不要假设埋点已经生效**：代码改动、SDK 初始化或计划发布之后，都要等待用户自行验证事件已实际触发。
- **不要默认发起质检**：即使用户已经确认事件触发，也只能在用户明确表示“开始质检”后再调用质检相关工具。
- **按阶段加载文件**：只读取当前阶段需要的 prompts、references 和 playbooks，不要一次性把全部共享资料灌进上下文。
