# Draft Output Playbook

用于把设计阶段的结论整理成可讨论、可落地的埋点方案草稿。

## 输出结构

至少包含以下部分：

1. 业务流程摘要
   说明这次覆盖哪些页面、模块、关键路径。

2. 事件清单
   每个事件至少包含：
   - 事件名
   - 中文含义
   - 触发时机
   - 端
   - 服务端 / 客户端归属
   - 属性列表

3. 用户标识方案
   只要涉及登录态，就单独给出：
   - `login_id`
   - `anon_id`
   - `identify` 调用点
   - `reset` 调用点
   - 服务端是否要透传 `anon_id`

4. 待确认问题
   把代码里无法直接确定的点列出来，方便用户补业务口径。

## 交付要求

- 方案要能直接交给研发实现，不要只给抽象建议。
- 事件与属性命名尽量统一，不要同一流程里混多种风格。
- 如果用户下一步要落到平台，明确说明可切到 [../../wave-tracking/SKILL.md](../../wave-tracking/SKILL.md)。
