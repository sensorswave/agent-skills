# Code Discovery Playbook

用于“根据当前代码设计埋点计划”时，先把业务流和关键动作盘清。

## 什么时候读

- 用户明确要求基于当前代码设计埋点方案
- 用户没有现成事件表，只给了代码仓库
- 需要从页面、接口、登录态中反推出触发点

## 执行步骤

1. 先读仓库规则
   先识别代码库已有的约束、目录分层和局部规则，再开始盘点业务流程。

2. 盘点入口与模块
   优先识别：
   - 路由 / 页面入口
   - 功能模块目录
   - 表单、弹窗、列表、详情页
   - 服务端 controller / service / API handler

3. 提取关键流程
   至少要定位：
   - 页面浏览
   - 关键按钮 / CTA
   - 表单提交
   - 成功 / 失败结果
   - 登录 / 注册 / 登出
   - 支付、下单、分享、邀请等业务关键动作

4. 判断上报归属
   对每个候选事件都要问：
   - 这是 UI 行为还是业务事实？
   - 能否在服务端得到更可靠的结果？
   - 客户端是否只需要补充上下文？

5. 识别现有埋点与命名
   如果代码里已存在 `track` / `capture` / `identify` / `reset` / 埋点 SDK 调用，先记录已有风格，避免新旧两套命名体系。

6. 标注不确定项
   代码无法确定的地方，不要硬猜；单独列成待确认问题。
